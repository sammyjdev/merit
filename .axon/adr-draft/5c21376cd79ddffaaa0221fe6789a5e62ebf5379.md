# Mail/Queue hardening with IMAP UID cursor & error handling

## Context

modifies merit/mail.py (adds SelectError, SearchError, _ok helper) and merit/queue.py (introduces UID‑based MailCursor and URL normalization logic)

## Decision

added explicit MailError subclasses (SelectError, SearchError) with a shared _ok validation helper, implemented a UID‑based cursor in Queue (MailCursor) to track processed messages, and normalised queue URLs via a new normalize_queue_url function

## Rationale

The change enforces a new constraint that any IMAP SELECT or SEARCH failure must raise a typed exception rather than returning ambiguous falsy values; this makes failure modes explicit and supports automated retry logic, addressing the masking bug observed on 2026‑07‑29. Using a UID‑based cursor instead of sequence numbers decouples processing from mailbox mutations, guaranteeing idempotent resume after crashes and enabling multiple workers to coordinate without relying on volatile message ordering—an important trade‑off between added implementation complexity and long‑term reliability. Normalising queue URLs eliminates inconsistencies caused by varied input formats, reducing coupling between callers and the queue subsystem and ensuring that downstream components see a canonical identifier, which aids future extensibility of queue back‑ends. These decisions were preferred over ad‑hoc error checks or retaining sequence‑number tracking because they preserve invariants, lower future maintenance cost, and align with the project's reliability goals.
