# Add separate 'track' CLI subcommand with ledger module

## Context

merit/cli.py (adds Typer subcommand track_app and imports merit.track); merit/track.py (new module implementing add/set/list for application ledger); .specs/features/application-ledger/validation.md (specifies behavior and mutation testing)

## Decision

Introduce a dedicated 'track' subcommand and a new merit.track module to handle application‑ledger operations (add, set, list) instead of embedding them in the existing CLI commands

## Rationale

The change creates a clear boundary between the core merit commands (queue, match, rank, etc.) and the newly‑introduced application‑ledger domain. By adding a Typer sub‑command (track_app) in merit/cli.py and a separate merit.track module, the developers enforce separation of concerns: ledger‑specific logic lives in its own module, reducing coupling to the rest of the CLI and making future extensions (e.g., additional ledger commands) easier to add without risking regressions in unrelated commands. This decision also improves testability—track.py can be unit‑tested in isolation, as shown by the extensive tests in tests/test_track.py and the validation spec file. An alternative would have been to append new commands directly to the main Typer instance, but that would increase the size and complexity of merit/cli.py, making it harder to maintain and increasing the risk of accidental side‑effects across commands. The chosen pattern respects the constraint of keeping the CLI modular and aligns with a domain‑driven approach where the ledger is treated as a first‑class subsystem. The inclusion of the validation spec ensures that mutation testing guards the new boundary against regressions, reinforcing the architectural intent.
