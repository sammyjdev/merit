# Mail/Queue hardening with IMAP status checks and UID cursor

## Context

merit/mail.py (IMAP interaction), merit/queue.py (URL handling), merit/cli.py (CLI entry point)

## Decision

Add explicit IMAP status verification, introduce a UID cursor in MailCursor, create SelectError and SearchError subclasses, and enforce URL normalization in queue processing

## Rationale

The change adds strict runtime invariants to the mail subsystem: IMAP SELECT and SEARCH responses are now validated via the new SelectError and SearchError types (see merit/mail.py) to distinguish malformed data from a genuinely empty mailbox. This prevents silent masking of bugs that previously manifested as zero‑message reads, a trade‑off that favors reliability over a slight increase in error‑handling code. Introducing a UID cursor (MailCursor.uid) enforces monotonic processing of messages, ensuring idempotent consumption and simplifying replay semantics; the alternative of relying on message sequence numbers was rejected because sequence numbers can change on expunge, breaking ordering guarantees. URL normalization in merit/queue.py standardises queue keys, eliminating duplicate entries caused by differing URL representations—a design decision that adds a small processing overhead but protects against subtle bugs in queue deduplication. Together these constraints reshape the mail‑queue boundary, making future developers aware that the system now expects explicit status checks, UID tracking, and normalized URLs to maintain correctness and low latency processing.
